reset() and destroying the injection context abort the calls in flight: their AbortSignal fires, they run no callback, and mutate() rejects with an AbortError. Aborting never undoes a write the server already received. Source: reset · queued reset · destroy

reset() during a call

No onSuccess, the status goes back to idle, and mutate() rejects with 'Aborted', the abort reason the fake API rejects with, as fetch() does. The server log shows the request was received: on a real server, the user may have been created anyway.

reset() while a call is queued

Both calls reject, and "Second" never appears in the server log. Its mutationFn never ran, so wasNeverSent(error) is true; "First" may have reached the server, so it is false.

Destroy

Destroying the injector aborts the call in flight, like navigating away from a component does. A mutate() after that rejects at once with 'Destroyed', and no request leaves. A longer-lived injector (a root service, or inject(EnvironmentInjector)) is how a write outlives the component.
