Three ways httpMutation() reads a response body: parse to validate or transform it, httpMutation.blob() / .text() for non-JSON bodies, and downloadProgress while it arrives. A fake HttpInterceptorFn stands in for the server, with artificial delays. Source

Validating the response with parse

"Create user (outdated response)" hits an endpoint that answers 201 with an old body shape ({{ '{' }} userId, fullName {{ '}' }}), so parse throws.

status
{{ createUser.status() }}
statusCode
{{ createUser.statusCode() ?? '—' }}
value
@if (createUser.hasValue()) { {{ createUser.value().name }} (#{{ createUser.value().id }}) } @else { — }
error
{{ createUser.error()?.message }}
With the outdated response, status is error while statusCode is still 201 and error is an HttpMutationParseError: the server has already applied the write. Treat it as a contract mismatch, not a failed write: retrying would create the user twice. Details in the recipes.

The fake backend emits progress events every 400 ms (an artificial delay).

{{ exportUsers.status() }}

@if (exportUsers.hasValue()) { Blob, {{ exportUsers.value().size }} bytes, type {{ exportUsers.value().type }} } @else { — }

The request has no body: the file comes back in the response, so it's a download. uploadProgress tracks the request body instead (see the httpMutation() page) and stays undefined here.
